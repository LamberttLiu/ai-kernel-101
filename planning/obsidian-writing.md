# 在 Obsidian 中跨端阅读与写作

所属专栏：《AI Kernel 101：从 Hello World 到 Flash Attention 的 Ascend C 实践》。本轮不迁移库，不改同步账户或远程设置。

# 同一个项目，两种入口

桌面进行工程管理时，从根目录 README.md 进入；手机阅读与改稿时，在 Obsidian 中打开根目录的 `00-写作入口.md`。该文件只保留在本地并通过 Obsidian 多端同步，不纳入 Git，也不作为公开文档的链接目标。文稿和配图都是同一套文件，不生成独立的手机镜像。

当前继续把项目根目录作为 Obsidian 库，保留原有 .obsidian 位置，不在 docs 或 planning 下另建嵌套库。拆出单独文稿库需要同时规划配置、同步根目录和跨边界链接，本次不进行这种迁移。

| 内容 | 位置 | 手机上的用途 |
| --- | --- | --- |
| 写作首页 | 00-写作入口.md | 快速打开正在写的文章与提纲；仅本地保留，通过 Obsidian 多端同步，不纳入 Git |
| 创意、随笔与临时想法 | planning/inbox | 统一收存；默认不进入 Git，新的普通笔记仍进入这里 |
| 文章正文 | docs/drafts、docs/articles | 直接阅读和修改原稿 |
| 系列计划与提纲 | planning | 调整结构、补充问题和论证 |
| 图片 | docs/assets/images | 阅读配图，粘贴图片时统一收存 |
| 源码与大型原始输出 | src、lab 等 | 主要在桌面处理；不作为手机写作的必要前提 |

给主要文稿与提纲设置了中文 aliases，保留稳定文件路径。别名属于 Obsidian 的标准属性，用于按中文名称引用文件；正文继续采用普通 Markdown 相对链接。[官方：Aliases](https://obsidian.md/help/aliases)

# 已配置的文件习惯

桌面当前库的 .obsidian/app.json 配置为：

- 新笔记默认放入 planning/inbox。
- 新附件默认放入 docs/assets/images。
- 使用 Markdown 链接和相对路径。
- 在 Obsidian 内移动或重命名文件时，允许自动更新内部链接。

Obsidian 支持指定新附件目录，粘贴与拖入的附件会写入默认位置。[官方：Attachments](https://obsidian.md/help/attachments)

这些设置针对当前本地库。手机是否接收它们取决于实际同步工具及配置；若不同步 app.json，应在手机“文件与链接”中设置同样的目录。此处没有创建同步连接，也没有更改远程账户或插件凭据。

可以用现有核心书签功能收藏写作入口。未安装自动首页插件，打开应用时仍按各设备当前工作区恢复；无需为了这个入口增加插件。

# 多端同步的范围

GitHub 负责项目版本与发布；Obsidian 的同步工具负责把本地 Markdown 和附件送到其他设备。.gitignore 只影响 Git，不能作为坚果云、Obsidian Sync 或其他服务的排除规则。

planning/inbox 默认仅本地是 GitHub 公开边界，不代表禁止手机与电脑同步私人笔记。两个既有文件保留原样并停止 Git 跟踪；通过 Obsidian 文件列表／快速切换打开，不依赖公开页面的本地文件链接。既有公开历史未清除，本轮也不修改历史。

建议手机优先拥有：写作入口、docs、planning，以及正文实际引用的其他文档和附件。不要只同步 Markdown 而漏掉图片；不要只复制正文，遗漏它引用的提纲或图片。

正文中的源码引用已在仓库合并时更新为 src 下的相对链接。若希望在手机上阅读这些实现与说明，应同步对应源码文件；只阅读正文时也可按需要保留它们。正文相对引用的 lab 记录和图表同样要进入同步范围；如果某目录被排除，对应链接在手机上就可能无法打开。

大型构建输出、二进制、profiler 输出、独立 sites 项目以及 Git 内部目录通常不需要进入手机。个人材料 .local 是否同步由作者单独决定，不能从它被 Git 忽略推断它不会被其他工具上传。

同步方式尚待作者确认：

- 如果使用官方 Obsidian Sync，在每台设备分别检查排除目录和配置同步选项。排除规则具有设备侧设置，不能只在电脑上配置一次就假定手机也相同。[官方：同步设置与选择性同步](https://obsidian.md/help/sync/settings)
- 如果使用坚果云插件或其他第三方同步，以该工具的实际文件过滤能力为准；当前只确认已启用 nutstore-sync 插件，没有读取账户配置或假定它已经连接成功。具体排除规则待确认同步方式后设置。
- 不让两套实时同步机制同时处理同一批文稿；若更换方式，先确认现有内容已完整落地，再切换。参见 [官方跨设备同步说明](https://obsidian.md/help/sync-notes)。

本说明是范围建议，不代表已在任何远程服务中应用排除规则。

# 一次手机改稿怎样回到工程流程

1. 打开 Obsidian，确认同步已完成，从写作入口进入原稿。
2. 直接改已有正文；中途创意、随笔、临时意见或零散思路统一写入 planning/inbox，可记入随手记或新建独立笔记。
3. 离开设备前确认改动已经同步，换到电脑后先接收这些改动，再继续写同一段。
4. 桌面集中整理图片名称、源码、数据与跨文档移动，运行项目链接检查，再进入定稿或发布流程。

若出现冲突副本，先比较并合并其中的修改，再移走重复文件；不要把带有未合并内容的冲突文件直接删掉。

文稿里的内部意见可用 HTML 注释简短记录，但发布前需要审阅移除；较长讨论放回 planning，避免正文堆积策划说明。

# 何时再拆文稿库

若后续使用的同步工具无法排除大型工程目录，或手机文件树被源码明显干扰，再考虑把所有文稿与配图聚合成一个独立的 writing 目录，作为唯一 Obsidian 库，与 src 等工程材料并列。届时需要一次性迁移全部文稿、配置和链接，并重新确认同步位置；仍然不维护两份正文。

现阶段先保持原库稳定，以入口、收件箱、别名和附件约定改善使用，避免在同步方式未确定时反复搬迁。
