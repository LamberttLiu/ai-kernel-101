# 先提出假设，再记录结果

实验必须说明问题、假设、对照与预期观察；锁定 shape、dtype、布局、数值范围、生成方法／随机种子（适用时）、Tile、Block、缓冲与临时区。每次改动说明改变了哪个变量，其余条件如何控制。

正确性先约定参考算法、参考精度、累计精度及误差指标。按问题选择最大绝对误差、处理近零分母的相对误差和必要的整体指标；不能看到结果后放宽阈值。固定输入 Add 的逐元素相等检查不直接作为 Softmax/Attention 的通用标准。

性能记录计时区间、是否包含初始化／分配／Host-Device 传输／启动、预热、重复、统计量和波动。记录 profiler 是否启用、工具版本、设备频率／功耗与并发状态（可取得时）。不把少数样本直接当稳定吞吐或瓶颈结论，预热20次、重复100次只能作为试跑起点。

失败同样归档：发生在哪一步、错误信息、退出码、是否属于设备不可用或语义错误、对假设的影响。缺失字段明确未知或未测，不能生成推测值填空。

# 数据与复现组织

以下是未来有真实实验时的组织示例，不代表结果已存在：

```text
lab/
└── vector-add/
    ├── README.md                   # 问题、环境、固定源码入口与复现方法
    ├── plot.py                     # 有实际图表时再增加生成脚本

            ├── figures/            # 本次数据生成的图
            ├── raw/                # 大型原始输出，仅本地
            └── profiler/           # 大型工具输出，仅本地
```

从 [模板](TEMPLATE.md)建立真实记录。正文、记录、代码提交、数据版本／哈希、图表和生成命令应能双向追溯。截图保留来源和原件，只作辅助；图表注明单位、统计口径和数据／计算过程。

大型 raw/profiler 默认不入 Git，记录保存位置、生成命令和必要校验信息；不能把唯一关键数据藏在忽略目录。公开正文只链接可公开、受版本管理的记录和图表。

# Attention 的检查门槛

沿用 [系列计划](../planning/series-plan.md)和第08篇已有论证，不重新设计路线。分别验证前向数学语义、shape/dtype/layout/mask、累计误差，以及分离基线与融合版本。Matmul 输出位置、Cube/Vector 交接、依赖与片上存储先做小规模验证；不以 CPU 正确、编译通过或模型预测替代目标设备融合与性能验证。
