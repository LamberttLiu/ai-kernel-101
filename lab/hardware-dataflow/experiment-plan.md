# 第02篇实验与配图设计

对应[第02篇正文](../../docs/drafts/hardware-dataflow.md)。本轮交付实验规格与配图规划；作者确认后才生成实现和测试代码。当前没有性能结论，不把已有 Add 历史记录当成本方案的测量结果。

# 验证范围与实施顺序

本文要验证三件事：源码中的容量与字节计数是否正确；改变输入规模与分块后，耗时趋势是否符合模型预期；哪些额外证据足以支持“带宽或计算资源限制了性能”的判断。

实施顺序为：环境与接口核对 → 独立模型计数检查 → CPU／SIM 可用范围内的功能检查 → NPU 正确性 → 独立 NPU 性能测量 → 结果分析与正文回填。每一步单独标记状态；CPU 或 SIM 不可用时记录原因，不能用其他模式补称通过。CPU／SIM 的耗时不进入真机 Roofline。

本篇不开展双缓冲调优、完整 Matmul 自动调参、跨核融合或 Flash Attention 性能优化。Add 与 Matmul 只做解释本篇模型所需的最小对照。设备条件或接口不满足时，保留模型与失败记录，缩小实验范围。

# 先检查手算模型

模型检查使用独立的小尺寸索引枚举，统计每个逻辑任务读写的元素与各阶段活跃缓冲；不是只把同一个公式抄两次断言相等。用闭式表达预测，再用枚举计数交叉检查。

| 模型用例 | 预期计数，全部为手算值 |
| --- | --- |
| Add， $L=16384$ 、 $T=2048$ 、FP32 | $F=16384\,\mathrm{FLOP}$ ；读 $131072\,\mathrm{B}$ ，写 $65536\,\mathrm{B}$ ，合计 $196608\,\mathrm{B}$ ；三块 UB 有效负载 $24576\,\mathrm{B}$ ／任务 |
| Add， $L=1048576$ 、 $T=2048$ 、循环处理 | $F=1048576\,\mathrm{FLOP}$ ； $Q=12582912\,\mathrm{B}$ ；三块 UB 有效负载仍为 $24576\,\mathrm{B}$ ／任务 |
| Matmul， $n=64$ ，理想输入各读一次 | $F=524288\,\mathrm{FLOP}$ ； $Q_{\min}=32768\,\mathrm{B}$ ； $I=16\,\mathrm{FLOP/B}$ |
| Matmul， $n=128$ ，理想输入各读一次 | $F=4194304\,\mathrm{FLOP}$ ； $Q_{\min}=131072\,\mathrm{B}$ ； $I=32\,\mathrm{FLOP/B}$ |
| Matmul， $n=128$ 、 $b=32$ ，独立输出块 | $Q_{\mathrm{tile}}=327680\,\mathrm{B}$ ； $I=12.8\,\mathrm{FLOP/B}$ ；16 个逻辑输出块 |
| Matmul， $B_M=B_N=64$ 、 $B_K=32$ ，单缓冲有效负载 | L1 输入共 $8192\,\mathrm{B}$ ；L0A／L0B 各 $4096\,\mathrm{B}$ ；L0C 部分和 $16384\,\mathrm{B}$ ；布局填充与预留另计 |

非整除 shape 暂不进入主性能对照。功能侧加入一次非整除任务分配，检查循环覆盖；若 Tile 本身需尾块处理，按已核对的安全搬运接口扩展后再测，不能静默越界或漏算。容量检查先按查询结果拒绝超额配置，不靠运行越界验证硬件容量。

# 正确性与数值判据

**Add**：使用同一组实际 FP32 输入构造参考，覆盖全零、正负整数、边界索引标记和固定种子的有限随机数。默认按逐元素绝对／相对误差检查，同时保存 bitwise 比较结果。有限正常值、同一舍入模式下的纯 FP32 加法预期可逐位一致；若出现差异，先核对舍入、非正规数处理与输入转换，不放宽阈值掩盖覆盖错误。索引标记和输出哨兵用于发现漏写、重复写与错位；零长度由 Host 明确拒绝或短路，不发起非法 Kernel。

**Matmul**：参考输入必须先量化到实际 FP16，再以 FP64 在 Host 计算乘积与求和，避免拿原始 FP32 数据作不公平参考。先测试零矩阵、单位阵、固定小整数和带符号随机数。随机数限制在 $[-0.5,0.5]$ ，固定种子并加一组抵消明显的输入；不在本篇引入 NaN／Inf 的完整语义验证。

记录最大绝对误差、逐元素最大相对误差（明确分母下限）及归一化 Frobenius 误差。暂定随机用例逐元素判据为：$$\lvert C-C_{\mathrm{ref}}\rvert \le 10^{-3}+10^{-3}\lvert C_{\mathrm{ref}}\rvert$$，再用 FP32 累计舍入尺度辅助诊断：$$u=2^{-24},\qquad\gamma_K=\frac{Ku}{1-Ku}$$，误差预算与 $\sum_k \lvert a_{ik}b_{kj}\rvert$ 同时记录。该舍入估计要求普通 FP32 累计且 $Ku<1$，不作为未知 Cube 累计语义的保证。阈值需在确认实际数值路径后、性能运行前冻结；若不通过，保存失败，不能根据测量结果事后放宽。

每一组计时前后均检查输出；性能采样与参考计算分开。CPU 功能通过不替代 NPU 数值通过，SIM 也不证明真机吞吐。

# Add：验证容量、流量与并行度

## A1：长度扫描，观察固定开销何时减弱

- 假设：在相同数据路径下 $I=\frac{1}{12}$ 不随 $L$ 改变；足够大时增加 $L$ 主要增加流式工作，小输入则可能受启动等固定开销影响。
- 配置：FP32， $T=2048$ ，单缓冲，连续独立 $x,y,z$ ； $L$ 取 $\{2^{11},2^{12},2^{14},2^{16},2^{18},2^{20},2^{22},2^{24}\}$ 。任务数 $G$ 固定为核对后的 AIV 工作配置 $G_{\mathrm{ref}}$ ，多余任务需能安全退出；任务按循环覆盖所有 Tile。
- 记录：实际非空任务数、每任务轮数、 $F$ 、 $Q_{\mathrm{logical}}$ 、容量有效负载、设备时间分布、 $\frac{F}{t}$ 、 $\frac{Q_{\mathrm{logical}}}{t}$ 。
- 预期：小输入未必线性；大输入有机会出现稳定的逻辑有效吞吐，但不预设出现范围或平台数值。
- 反例：吞吐不稳定或大输入仍明显受任务分配影响时，转 A2 排查，不给出“已带宽受限”的结论。

## A2：固定流量，检查并行任务不足

- 固定 $L=2^{22}$ 、 $T=2048$ 、相同输入地址与运算； $G$ 候选为 1、2、4、8 及 $G_{\mathrm{ref}}$ ，并去重、过滤不合法配置。实际数值在确认设备后冻结。
- 每任务处理的 Tile 数可变化， $F$ 与 $Q_{\mathrm{logical}}$ 必须保持不变；不同时改变 Tile、缓冲份数或指令路径。
- 比较时间、任务负载和可用的搬运／Vector 指标。若增加任务数显著改善性能，只能先说明此前并行工作不足；若继续增加不再改善，也要结合 A3 才能判断是否接近带宽限制。
- 空任务、波次数、负载不均和循环控制也会影响结果，全部记录，不能把逻辑任务数当作物理核数。

## A3：缓存与流量口径交叉检查

- 对同一组大 $L$ 分别测重复同一地址的热数据模式与轮换不重叠缓冲的流式模式；轮换集需按实际缓存容量设置，目标工作集大于相关缓存且不超过安全可用显存。若容量未知，只能标记为轮换地址测试，不能称“冷 HBM”。
- 采用输入输出比例匹配的独立流式基线估计可达到的吞吐；其结果仅称实测参考水平，不是被证明的硬件绝对上限。若无法实现独立基线，不用 Add 自身的最大值循环证明 Add 已达到带宽上限。
- profiler 若提供已核对定义的 HBM 读／写字节或速率，分别记录读、写、总量与时间窗；不把 GM 请求数当作 HBM 事务数。工具不支持时写“不可观测”。
- 判断： $Q_{\mathrm{HBM}}$ 与 $Q_{\mathrm{logical}}$ 相近且与独立基线及任务扫描共同支持时，才讨论当前配置下外部带宽的约束；否则缩小到“逻辑有效吞吐与并行度／缓存相关”的结论。

# Matmul：验证理想复用与分块重读

## M0：先核对接口与一个最小正确结果

核对目标设备的输入类型、累计、FP32 结果输出、输入格式与转换、 $K$ 分段同步。选择 $n=64$ ，再用 $n=128$ 检查至少两个 $K$ 片段的累计，禁止每段重新清零。若高阶 Matmul 无法控制或观测所需参数，先作为功能／性能基线，不用于证明后续独立输出块流量公式。

M0 不通过时停止 M1—M3 的性能推断，保留错误、版本与不支持项。独立 Matmul 属于待实现基线，不直接把其他算子里的子步骤当作本篇已验证实现。

## M1：规模扫描，比较 $\frac{n}{4}$ 与真实任务规模

- 稠密方阵 $n$ 候选为 64、128、256、512、1024；设备内存、运行时长或接口受限时缩小集合并记录。
- 初始 $B_M=B_N=64$ 、 $B_K=32$ ，单缓冲，输出块按固定调度策略分配给核。超额输出块分轮执行，不假定一块输出独占一个物理核。
- 固定实际 FP16 输入、FP32 累计／输出， $\beta=0$ 语义，不读取旧 $C$ ；仅测 Kernel，若存在独立布局转换，另测并报告“转换＋Kernel”的组合时间。
- 每点同时列 $F$ 、 $Q_{\min}$ 、按真实循环统计的 $Q_{\mathrm{logical}}$ 、输出块数、实际核配置与 $t$ ； $\frac{Q_{\min}}{t}$ 只能称理想流量口径下的数值。
- 预期：规模增大提供更多工作与复用机会，但不能从吞吐增加直接断言达到 Cube 屋顶；观察是否受并行块数、重读和布局开销影响。

## M2：固定 $n$ ，改变输出块检查复用

- 固定 $n=512$ 、 $B_K=32$ ， $B_M=B_N=b$ 候选为 32、64；只有二者均满足布局、容量与接口限制才比较。 $b=128$ 仅在容量预算和接口核对后追加，不列为必做。
- FP16／FP32、同一输入、物理核配置、单缓冲与计时范围不变；改变 $b$ 必然同时改变逻辑输出块数和局部负载，这些作为共同变化量报告，不宣称纯粹隔离了某一个变量。
- 对独立输出块方案， $Q_{\mathrm{tile}}=\frac{4n^3}{b}+4n^2$ 。 $n=512$ 时， $b=32$ 预计 $Q_{\mathrm{tile}}=17825792\,\mathrm{B}$ 、 $I\approx 15.06$ ； $b=64$ 预计 $Q_{\mathrm{tile}}=9437184\,\mathrm{B}$ 、 $I\approx 28.44$ 。以上是逻辑计数预测，不是实测 HBM。
- 同时核对读取调用、枚举计数与可用的物理计数器。若 $Q_{\mathrm{HBM}}$ 没随逻辑读取同幅下降，检查缓存命中与事务；若实际高阶接口调度不符合假设，重建模型，不将差异归咎于硬件。
- 若大块更慢，检查任务规模、容量／布局、搬运流水与尾波；保留失败配置，不只挑最快点展示。

## M3：建立独立计算参考并定位屋顶差距

- 只有可核实的官方同精度稠密上限才进入“理论屋顶”；未知时不填硬件数值。条件允许时，以可追溯的库 Matmul 或独立优化基线作实测参考，并注明它可能采用不同调度与数据格式。
- 若只有有限规模的基线，称“参考吞吐”，不称“实测峰值”。Vector FP32 与 Cube 混合精度分别画图，不能共用一个计算屋顶。
- 存储边界也要匹配：有 $Q_{\mathrm{HBM}}$ 时画 $I_{\mathrm{HBM}}=\frac{F}{Q_{\mathrm{HBM}}}$ 的 HBM Roofline；只有 $Q_{\mathrm{logical}}$ 时画逻辑工作量图，不用 HBM 带宽曲线作严格利用率结论。
- 若实测点高于理论屋顶，首先检查单位、FMA 计数、稀疏／稠密、核数范围、时间窗和缓存边界，不直接视为发现超峰值性能。

# 计时与重复协议

1. 所有输入生成、显存分配、H2D、D2H、参考比较与打印均在 Kernel 计时区间外。运行前清理同一 Stream 上无关工作，使用已核对可用的设备侧计时接口或工具；API 不支持时保留 Host 同步计时但单列口径，不能称纯设备执行时间。
2. 每个配置先预热 20 次；分 5 组，每组至少 50 次。使用设备事件批量计时时以组总耗时除以次数，保存组平均；若工具提供逐 Kernel 耗时，则同时保存逐次样本。两种样本不能混称，分别报告中位数、四分位范围及 min／max。
3. 小 Kernel 若接近分辨率，提高批次数，直到总时间至少覆盖计时分辨率的 100 倍；将批次结果标为稳态平均，不能当作单次启动延迟。流式模式使用独立轮换缓冲协议，不能因重复次数增加把整个实验变为热缓存测试。
4. 配置执行顺序做固定种子的随机化；记录设备共享情况和可见频率／温度。异常值保留并说明原因，不默认删除；测得波动大于候选差异时，不给出加速结论。
5. profiler 单独采集，核对采集配置是否改变 Kernel 形态；普通计时与分析计数以同样输入、配置和代码版本关联，采集耗时不与无采集耗时混用。
6. 不通过正确性的配置不进入吞吐比较。运行失败、超时、不可用计数器、无法固定的设备条件均作为结果记录，不补齐缺失值。
