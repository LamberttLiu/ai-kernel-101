# AI Kernel 101：从 Hello World 到 Flash Attention 的 Ascend C 实践

以 Ascend C 为实践载体，从第一性原理理解 AI Kernel 的设计与性能优化。

知乎、微信公众号、小红书共享一份权威 Markdown。GitHub 展示源文件与复现材料，不等于文章已经在三个平台发布。当前没有可确认的社交平台发布记录，不依据文件日期补填发布时间。

# 平台分工与适配

| 平台 | 主要内容 | 允许适配的部分 |
| --- | --- | --- |
| 知乎 | 完整论证、机制、实验及技术问答 | 标题长度、导语、公式代码、站内链接与阅读引导 |
| 微信公众号 | 系列长文、完整推导与连续阅读 | 手机排版、系列目录、图表尺寸、代码呈现与上下篇导航 |
| 小红书 | 核心问题图卡、实验对照与精简解释 | 分页、文字密度、图表尺寸和精简导语；仍需交代证据与边界 |

适配不能改变算法语义、结果、因果结论或验证范围。代码截图或精简图卡应提供源文章／仓库入口；不把预测图画成实测图，不通过删去限制条件制造性能结论。

# 版本与状态

正文在 docs/drafts 或 docs/articles 保持唯一来源；文章是否定稿与是否发布分别记录。每次发布从 [发布与复盘模板](TEMPLATE.md)开始，建立实际篇章的记录，不预建十份空文件。

记录源文件和固定提交、代码提交、实验记录／数据版本、图表来源、平台适配差异、真实链接、时间、勘误与更新。状态分别使用“未确认、待审核、待适配、待发布、已发布、待同步、已撤下”等实际适用值；只有作者确认或授权渠道验证的真实发布，才标为已发布。

源文实质修订后逐平台检查版本差异；不把修订后的正文版本自动赋给旧平台文章。适配副本导出到被忽略的 publishing/exports，随时可重新生成，不成为新的权威原稿。

# 发布前与发布后

发布前完成 CONTRIBUTING 中的六阶段审核，检查平台预览、公式、图表单位、手机可读性、代码、来源、链接和私密信息。仓库相对路径在平台上换成真实固定版本链接，图片上传状态在发布时确认。

发布后手动记录技术评论、新问题、勘误和下一篇改进。阅读、曝光、收藏、互动、关注转化等数据可以手动填入或经明确授权导入；未知则留空，不生成估计值充当运营数据。含账号或商业敏感信息的完整复盘仅存 .local，公开记录只保留适合公开的技术反馈和结论。

本轮不实现自动发布、平台爬取、账号连接或增长系统。GitHub 推送与三个平台发布均需要另行明确授权。
