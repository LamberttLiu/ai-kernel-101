# AI Kernel 101：从 Hello World 到 FlashAttention

> 基于 Ascend C 的算子设计与性能优化实践

以 Ascend C 为实践载体，从第一性原理理解 AI Kernel 的设计与性能优化。本目录管理 16 篇核心文章、5 个知识阶段。具体文章规划可以参考：[系列文章规划](../planning/series-plan.md)。

# 撰写流程阶段

**工作区文章统一使用以下八个阶段。** `docs/drafts` 中每篇文章在 YAML frontmatter 的 `writing_status` 字段填写下表中的完整阶段名称，不使用简称、自由描述或多个状态拼接；本页目录同步展示相同阶段。具体缺项写入 `to_do_list`，实验证据与发布记录分别维护。

| 阶段  | writing_status     | 阶段含义与推进条件                                 |
| --- | ------------------ | ----------------------------------------- |
| 1   | 提纲                 | 明确核心问题、论点、论证顺序与验证需求，尚未进入完整正文撰写。           |
| 2   | 初稿完成中              | 正文正在撰写，论证或必要段落尚未齐备。                       |
| 3   | 初稿完成，实验待设计         | 初稿论证已连贯，待明确实验假设、对照、输入、指标与判据。              |
| 4   | 初稿完成，实验待运行         | 实验方案已明确，待完成必要实现、环境准备与运行；具体阻塞项记录在待办中。      |
| 5   | 初稿完成，实验已运行，结果待分析   | 本篇所需实验已执行且证据已归档，待检查正确性、解释结果并核对模型。         |
| 6   | 初稿完成，实验结果已分析，配图待补全 | 结果分析已回填正文，结论与边界已有依据，待补齐插图、图注与来源。          |
| 7   | 初稿完成，配图已完成，待发布审核   | 正文、实验分析和配图齐备，待完成技术、语言、来源及平台发布检查。          |
| 8   | 已完成                | 发布前审核通过，待办已处理，正文已定稿；由 drafts 移入 articles。 |

阶段按当前尚未完成的最早环节判断，允许提前开展后续工作；已有部分实验或配图，不代表前置工作已经完成。新增缺项或审核发现问题时，回退到对应阶段，并同步更新正文 frontmatter 与本页目录。初稿完成允许保留明确的实验与配图占位，不允许把未取得的结果写成结论。

实验状态以本篇明确的验证范围为准：CPU／SIM／NPU 功能与性能证据不能相互替代，历史局部测试不能代替待补实验。若文章不需要新增实验，应在 `to_do_list` 中注明无需新增实验的理由、适用范围及已有证据入口，再越过不适用环节；不虚构运行或分析记录。

`writing_status` 管理撰写流程，`publication_status` 单独记录平台发布状态。“已完成”表示定稿完成，不表示已发布；实际发布链接、版本与勘误仍以 [publishing](../publishing/README.md) 为准。八阶段用于进度管理，既有六阶段质量审核仍作为审核要求。仅列入系列计划、尚未形成提纲的篇章在目录中以“—”表示，不另设第九种状态，也不生成空正文。

# 正文与素材

```text
docs/
├── README.md              # 篇次、标题、材料与实际状态
├── ARTICLE_TEMPLATE.md    # 内部写作与审稿提示，不是固定章节模板
├── drafts/                # 当前写作的权威正文
├── articles/              # 实际定稿，由 drafts 移入
└── assets/
    ├── figures/           # 文档插图；plans 规划、src 代码、gen 图片
    └── brand/             # 品牌标识、横幅与生成材料
```

定稿时移动同一份正文，不另复制平台原稿。修改对外标题优先改标题元数据、别名和目录，保留现有稳定文件名；必要移动时同步修复链接。章节内的“一、二”等章节编号不等于篇次。

正文只保留论证必需的代码；完整实现、构建配置、实验设计、数据与分析报告统一按主题放在 lab。图片和引用采用标准 Markdown 相对链接，带空格路径用尖括号包裹。公开文件不链接到仅本地存在的 inbox、账号配置或原始数据。

草稿与定稿共用 `assets/figures/plans` 中的插图规划，与生成代码和图片统一管理。新增代码配图按[Matplotlib 绘图工作流](assets/figures/README.md)生成，正文引用 `assets/figures/gen` 中的 PNG，插图按出现顺序从 `fig1` 编号，品牌图片直接引用 `assets/brand` 中的文件，具体使用见 [品牌素材说明](assets/brand/README.md)。

审核修改文章的时候，将后续待完成的整理归纳在文章前 frontmatter 的 to_do_list 字段内，正文中使用占位符。
