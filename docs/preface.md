# 序言

我一直有个习惯，学到一点新东西，就试着把过程写下来，分享到知乎或 GitHub 上。有时，写着写着才发现，自己虽然知道怎么把一段代码跑起来，却还说不清楚它为什么要这么写。做 AI Kernel 101 的念头，就来自这种写作和学习的经历。我想把自己做算子开发时遇到的问题、走过的弯路和后来想明白的事情，慢慢整理成一套能前后串起来的经验，也给刚接触这个领域的人留一份可以动手跟着做的参考。

2025 年，我开始用 Ascend C 在昇腾 NPU 上做高性能算子开发。那时，大模型已经受到广泛关注，AI 编程助手在我的工作里还没有广泛普及。我接触到的高性能算子开发资料，大多围绕 NVIDIA GPU 和 CUDA 展开。从官方文档、开源代码到性能优化文章，甚至还有 LeetCUDA 这样的练习项目，遇到一个问题，往往能找到好几种解释和可以对照的实现。到了 CANN 这边，我能找到接口说明和样例，但要把这些材料串起来，弄明白一个算子从哪里写起、怎么验证、性能慢了又该查哪里，常常得自己边做边找答案。

我就从官方文档和样例出发，在实际环境里一点点开发、调试和验证。做得越多，我越想把其中的一些判断说清楚。比如，一个逐元素加法写出来很简单，可一旦问起时间花在哪里，就得算清楚读了多少数据、写了多少数据，再去看实测耗时是否符合预期。改了 Tiling 或者开了 Double Buffer，如果结果和预期不一样，这个偏差本身就值得记下来。它可能促使我重新检查性能模型里漏掉了什么，也可能让我意识到，这次实验的条件还不足以回答最初的问题。我想把这样的过程也写进来，让读者看到一个结论是怎么得出来的。

因此，这个系列会从一个能跑通的 Hello World 写起，沿着数据搬运、分块、流水、归约和矩阵乘，一步步走向 FlashAttention。代码和实验以 Ascend C 为主，遇到适合对照的问题，也会借用其他编程模型里的例子。我希望，当读者以后换一种语言、换一块硬件，或者接手一个陌生算子时，还能从算子要算什么、数据怎么走、时间花在哪里这几个问题入手，自己推导、测量和判断。

到 2026 年末再回看，AI 编程工具的进步已经超出了我刚开始做算子时的预想。现在，写出一版可以尝试的实现快了很多，我也更容易在代码跑通以后才发现，自己还有几个关键问题没想明白。所以这个项目也给我留了一个练习的机会。遇到一个问题，我想先自己写出基线，想一想结果应该是什么样，再用实验去验证。AI 可以帮我查资料、读代码和排错。最后写进文章的判断，我希望自己能讲得清楚，也能拿出相应的实验记录。

这两年，国内对自主 AI 基础设施的重视，也让我更想把自己在昇腾上的实践记录下来。我期待 Ascend C 和 CANN 在国内的 AI 开发中发挥更大的作用，也希望后来的人能找到更多可以直接动手的材料。

**AI Kernel 101** 这个名字，来自我刚参加工作时读过的 《[LeetCode 101](https://haoming-luo.com/Doc/Machine_Learning/LeetCode%20101%20-%20A%20Grinding%20Guide.pdf)》。那时候，我还在靠一题题手写来补数据结构和算法。这本书帮我把零散做过的题放进一个框架里，慢慢看出它们之间的联系。「101」也常用在大学入门课程的编号里。我借用这个名字，是希望给刚接触算子开发的人一个起点。要是读者有一天遇到一个从没写过的算子，能像我当初读《LeetCode 101》时那样，从已经做过的几个例子里找到下手的地方，这个系列就有了我最初希望它有的用处。
